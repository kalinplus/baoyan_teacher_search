# Task0 规则驱动抓取方案

## 1. 问题定义
不同学校/学院的教师列表页面结构差异很大，常见差异包括：
- 人名区域与导航区域混杂
- 分页方式不同（下一页、页码、参数翻页）
- 列表可能在二级页面
- 部分页面为滚动加载或脚本渲染

因此，不能依赖单一通用正则，也不应依赖人工先给页面结构说明；应采用“自动整页识别优先 + 站点规则兜底”的方式逐页打通。

## 2. 目标
- 输入：学校 + 学院 + 列表 URL
- 输出：`output/teacher_pool/{学校}/{学院}/teachers.json`（姓名 + 详情URL + 可直接抽取的基础字段）
- 质量目标：
  - `teachers` 非空
  - 无重复
  - 不包含明显导航词、分页词、栏目词
  - `teacher_profiles` 与 `teachers` 数量对齐
  - 详情页 URL 可解析且可追溯来源（没有详情页时允许 `null`）
  - 能提取到的邮箱、研究兴趣、职称应同步写入（提取不到时置空，不静默伪造）

## 3. 总体方案

### 3.1 抓取层（通用）
- 负责请求页面、编码处理、分页遍历、输出落盘。
- 默认使用 `requests` 抓取 HTML。
- 该层不负责判断“哪些文字是姓名”。

### 3.2 页面探针层（通用，新增）
- 先对整页做结构扫描，识别候选“教师条目容器”（card/list item）。
- 识别线索包括：
  - 包含 2-4 字中文姓名模式的节点
  - 节点内存在 `a[href]` 且 href 非导航锚点
  - 节点邻近出现邮箱正则命中（`xxx@yyy`）
  - 节点邻近出现研究方向关键词（AI、机器学习、计算机视觉等）
  - 节点邻近出现职称关键词（教授/副教授/助理教授/研究员）
- 输出候选节点及置信度，用于后续自动提取。

### 3.3 提取层（自动优先，规则兜底）
- 优先走自动提取：基于页面探针结果抽取 `name/profile_url/email/interests/title`。
- 自动提取失败或误差过高时，回退到站点规则（适配器）。
- 规则描述“从哪里取姓名与链接/字段”，例如：
  - 目标容器特征（class/id/模块标题）
  - 目标节点模式（如 `a` 标签文本 + `href`）
  - 分页入口规则（next 链接、页码链接）
- 提取结果进入统一清洗流程，并统一转为 `teacher_profiles` 结构。

### 3.4 清洗层（通用）
- 去空、去重、长度过滤（中文 2-4 字为主）
- 黑名单过滤（如：首页、上页、下页、尾页、学院、通知）
- URL 规范化（相对路径转绝对路径、去空白、去锚点）
- 邮箱规范化（小写化、去空白）
- 兴趣字段规范化（按分隔符切分，去重去噪）
- 保持失败显式：抽取为空时直接报错，不静默降级。

### 3.5 验证层（通用）
- 自动校验：非空 + 去重
- 自动校验：`teachers` 与 `teacher_profiles.name` 集合一致
- 自动校验：URL 覆盖率统计（有链接/无链接）
- 自动校验：email/interests/title 字段存在性（允许空值，不允许缺字段）
- 人工抽样：每个学院至少抽样 10 条人工确认
- 若误提取明显（导航词较多或链接明显错误），视为失败，不写入“通过”结论。

## 4. 不依赖外部 API 的结论
这部分可以不使用外部 API：
- 第一阶段直接基于学院官网页面抓取（HTTP + 规则提取）即可。
- 仅当页面必须执行前端脚本才能拿到数据时，再评估引入浏览器渲染方案。
- 若需要新增依赖（例如浏览器自动化），先审批再落地。

## 5. 实施计划（可执行）

## 实现说明（已落地）

### 输入 HTML 特征（页面探针）
- 先扫描整页 `<a href="...">...</a>` 锚点，筛出可达链接（排除 `#` 与 `javascript:`）。
- 在锚点文本与邻域上下文（前后约 600 字符）中识别候选姓名：2-4 字中文模式优先。
- 同时探测富字段信号：
  - 邮箱：正则 `xxx@yyy`
  - 职称：教授/副教授/助理教授/研究员等关键词
  - 兴趣：`h1-h6` 标题与“研究方向/研究领域/Research Interests”语义片段

### 字段判定逻辑
- `name`：锚点文本中最高置信度中文姓名（首 token + 中文姓名模式兜底）。
- `profile_url`：锚点 `href` 归一化后的绝对 URL。
- `email`：锚点文本与邻域上下文中的首个邮箱命中。
- `title`：邻域文本中的首个职称关键词命中。
- `interests`：标题/关键词片段按 `、,，;；/|` 切分，保留学术关键词短语并去重。
- `source_url`：当前列表页 URL。

### 兜底触发条件
- 自动流程得到空结果时触发站点规则兜底。
- 自动流程结果质量低于规则结果时触发替换（优先比较：URL 覆盖率 + 富字段覆盖率，其次比较人数与字段完整度）。
- 兜底后仍为空则显式失败（fail fast），不静默写入空名单。

### 当前规则兜底接口
- 在 `src/teacher_extractors/thu.py` 中，规则保持原有姓名提取兼容能力。
- 新增人工智能学院富字段兜底（全职 PI 分段）：
  - 区间：`sz2 -> sz3`
  - 从人员卡片解析 `name/profile_url/email/interests/title`
  - 仅在自动流程失败或明显劣化时启用
- 在 `src/teacher_extractors/sjtu.py` 中，新增上海交通大学兜底规则：
  - `soai.sjtu.edu.cn/cn/faculty/zzjs`：仅提取 `facultydetails` 人员卡片链接并解析 `email/title/interests`
  - `soai.sjtu.edu.cn/cn/teacher/spkz`：复用卡片提取逻辑，过滤导航链接与无富字段噪音项
  - `www.cs.sjtu.edu.cn/jiaoshiml.html`：优先调用 AJAX 接口 `active/ajax_teacher_list.html` 解析名录；若接口结果为空再回退到 CSE 旧页 `People.aspx?id=9`
  - `cs.sjtu.edu.cn/cse/People.aspx`：从 `PeopleList` 解析 `h2姓名 + PeopleDetail链接 + 研究领域`

### Milestone A: 规则框架落地
- 改造 `src/teacher_list_collector.py`，新增页面探针与自动提取流程。
- 先内置少量规则，不引入新依赖。
- 输出升级为“兼容旧字段 + 新增 URL 字段”。

验收：
- 至少 1 个学院页面在无人工结构提示下准确提取并通过姓名/URL 对齐校验。

### Milestone A.1: 一次性建设 AI 分析驱动提取流程（核心）
目标：只做一次能力建设，后续学院复用同一流程，不再逐页人工设计提取规则。

抓取 HTML 后的具体代码逻辑：
1. 解析阶段（parse_html）
- 输入：列表页 HTML + 当前页面 URL
- 输出：DOM 树 + 所有候选节点（a/div/li/article/section）

2. 候选块识别阶段（detect_teacher_blocks）
- 对每个候选节点计算特征分：
  - 是否包含中文姓名模式（2-4字）
  - 是否包含 `a[href]` 且非导航链接
  - 是否包含邮箱正则命中
  - 是否包含职称关键词（教授/副教授/助理教授/研究员）
  - 是否包含兴趣关键词（AI、学习、视觉、系统、网络等）
- 分数高于阈值的节点作为教师卡片候选。

3. 字段抽取阶段（extract_profile_fields）
- `name`：候选块中最高置信度中文姓名文本
- `profile_url`：候选块内最接近 `name` 的 `a[href]`，相对路径转绝对路径
- `email`：候选块内邮箱正则首个命中
- `interests`：候选块内兴趣文本按分隔符切分并去噪
- `title`：候选块内首个职称关键词命中
- `source_url`：当前列表页 URL

4. 规范化与去重阶段（normalize_and_dedupe_profiles）
- 统一规范 URL、邮箱、兴趣词
- 以 `name` 为主键去重（同名保留字段信息更完整的一条）

5. 质量判定阶段（quality_gate）
- 校验 `teachers` 非空
- 校验 `teachers == teacher_profiles.name`
- 统计 URL/邮箱/兴趣命中率
- 若低于阈值则触发兜底规则。

6. 兜底阶段（fallback_rules）
- 仅在 `quality_gate` 失败时调用站点规则（如 `teacher_extractors/thu.py`）
- 兜底后重复质量校验，仍失败则显式报错（fail fast）

### Milestone B: 分页与二级页支持
- 增加“下一页/页码”遍历。
- 增加“列表页 -> 详情页”模式（仅当人名在详情页时启用）。

验收：
- 至少 3 个学院页面稳定通过。

### Milestone C: 学院规则扩展
- 优先尝试自动识别；仅当自动识别误差不可接受时再新增站点规则。
- 每新增一个学院，附带一条运行记录和抽样结果。

验收：
- 当前任务列表里的页面逐个打通，失败页面给出可复现原因。

### Milestone D: 结果质量门禁
- 增加轻量质量检查（黑名单命中率、疑似非姓名比例）。
- 增加 URL 质量检查（无效协议、空链接占比、重复链接占比）。
- 增加字段质量检查（邮箱命中率、兴趣非空率、职称命中率）。
- 质量不达标直接失败，避免“看似成功”的脏数据流入任务1。

验收：
- 不再出现大规模导航词混入 `teachers`，且 `teacher_profiles` 可用于任务1主页预筛。

## 6. 协作输入模板（你提供，我实现）
默认只需要以下最小输入：
1. 学校
2. 学院
3. 列表页 URL

可选补充（仅用于加速排障，不是前置必需）：
4. 分页类型（无/下一页/页码/滚动加载）
5. 该页可确认的 5-10 个姓名样本
6. 是否需要登录、验证码或特殊请求头

建议格式（最小版）：

```md
学校：北京大学
学院：计算机学院 & 王选计算机研究所
URL：https://cs.pku.edu.cn/szdw/jyxl/amz/ALL.htm
分页类型：页码（可选）
姓名样本：张三、李四、王五...（可选）
限制：无登录，无验证码（可选）
```

## 7. 风险与边界
- 对脚本渲染站点，纯 requests 可能拿不到完整数据。
- 对强反爬站点，可能出现 403/验证码，需要单独策略。
- 部分学院页可能只有姓名无详情链接，此时 `profile_url` 允许为空，不作为失败条件。
- 本阶段优先“准确性与可复现”，不追求一次覆盖所有学校。
